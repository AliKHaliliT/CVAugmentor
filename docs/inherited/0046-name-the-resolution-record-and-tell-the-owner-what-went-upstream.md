# 0046. Name the resolution record and tell the owner what went upstream

Status: Accepted
Date: 2026-09-08

## Context

The law made a child write its upstream report and never made it say so. The
adoption gate asked the closing note to state that nothing qualified, but only
at adoption; in ordinary work the defect class put entries into STATE until
"the report is sent", and nothing said when that was or who would hear of it.
The owner of the style found a project's resolution record by opening its
upstream folder, and had been checking by hand whether anything had been filed
at all. The resolution record itself, introduced when the reply stopped being
owed, had a place and no name, so each agent would have named it its own way.

## Decision

A report is written in the same change that closes the work which produced
its entries, so an entry is held in STATE.md only between the workaround and
that close. The closing note of every delivery names each report written in
that change by path and each entry still held, or says there are none, and
the delivery gate's upstream-honesty item holds all three. The resolution
record written at re-alignment is named
`YYYY-MM-DD-resolution-short-kebab-title.md`, beside the report it resolves
and the reply that answered it, so the three kinds in the folder tell
themselves apart by name in every project.

## Options considered

- A mechanical signal was refused. Whether an agent told its owner is not a
  fact a tree holds, and an advisory that repeats on every run until a
  report is resolved would demand a written dismissal at every delivery
  while teaching the reader to skip it.
- Leaving the cadence to judgment was refused, because a held entry with no
  deadline is the same silence the defect class was written to end.

## Consequences

An owner reads the closing note and knows whether anything went upstream, and
where. A held entry cannot outlive the work it came from. A folder of
reports, replies, and resolutions reads the same in every project.
