# 0040. Carry the tool configuration as law and hold the docstring rhythm

Status: Accepted
Date: 2026-09-04

## Context

Asked whether it had rewritten the code into the style, the adopting
repository's agent answered plainly that it had not: its two hundred and
fifty-three repaired docstrings satisfied every audit rule and none of the
dialect, because presence was what the audit held. It also found the cause
in its own tree. It had selected the full docstring ruleset with the numpy
convention, which mechanically forbids the house rhythm, while the style's
own configuration selects presence codes only and carries a comment saying
why. Nothing in the style had said that the tool configuration was law, so
a child could rewrite the lint selection and no rule or check objected.

## Decision

The lint, type-check, and import-contract settings the style ships, with
the comments that give their reasons, are style-owned law like the
rulebook. The Adopting section says so, names them among the files a child
carries verbatim with only its own package names re-adapted, and gives the
reason: a selection the style refused forbids the rhythm the exemplars
carry. The docs audit holds that rhythm where a rule can see it: a blank
line after the header, a lone triple quote and a blank line to open, a
blank line and a lone triple quote to close, a blank line before the body,
two blank lines before every section header, and every parameter entry
typed as name : type. Whether a docstring says something true stays with
review.

## Consequences

A docstring that is present and wrong fails the gate. A child that widens
its lint selection past the style's diverges from carried law and the
re-alignment recopies the selection. This is the third time presence-only
checking let an agent stop at presence, and it is the last, because the
shape is now decided rather than read.
