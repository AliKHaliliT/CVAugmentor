# 0041. Anchor history-reading checks to their scope and sweep what retired rules produced

Status: Accepted
Date: 2026-09-04

## Context

The adopting doctoral repository re-aligned to the record-folder rule and
its gate went red over twenty-eight edits made two days earlier to
documents that were living then and became records on the reshape day.
The immutability check dated its own arrival by searching history for its
function's name, and that repository had written a check by the same name
before the family adopted the idea from it, so the widened rule found the
older arrival and reached behind itself. Nothing in a tree can unmake a
commit and a child may not edit carried law, so the gate could not go
green. The same pass showed a second leftover class: the repository's
earlier lint selection had required a docstring on every module, a shape
none of the family's package modules carry, and reverting the selection
stopped the requirement without removing what it had produced.

## Decision

A check that reads history binds from the arrival of its own scope, found
in the tree's own history and dated by the sentence that states the scope,
never by a name or a date a child's past could already carry; when the
scope changes, the sentence changes with it, so the anchor moves forward by
construction. The immutability check in every audit now carries that
sentence and searches for it, and the host's selftest proves the anchor is
the commit that introduced it. The agent guide states the rule beside the
one on checks implying no more than they decide, and tells a re-aligning
child that a red gate over older commits is a defect to send upstream,
never a reason to rewrite history.

A module in the Python styles carries no docstring; its name and its room
in the map say what it is, and only a script run as a command opens with
one. The code-level section says so and the docs audit fails a module
docstring under a package root, with scripts outside its reach.

Re-alignment sweeps what retired rules produced. For every rule the child's
configuration had and the style's does not, the artifacts that rule
required are removed and the sweep listed in the inventory, because the
rule's absence in the template is a refusal rather than an oversight. The
gate gains the matching item.

## Options considered

- Anchoring the rule to the README's alignment pin was refused, because
  the pin names a template commit, which bounds no range in a child's
  history, and the template itself has no pin.
- A closed list of forbidden code artifacts was refused. It cannot be
  complete, reads as noise to a capable model, and would imply more than
  it decides; the finite diff of the child's configuration against the
  style's does the enumerating instead, and each leftover class met in
  practice becomes a named negative in the check.

## Consequences

A widened history-reading rule never re-judges commits legal under the
narrower one. Two hundred inherited module docstrings fail a gate instead
of surviving as drift. A re-aligning agent has a decidable list of what to
sweep and a place to record that it swept it.
